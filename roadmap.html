Fix before any store sees it

Four things would have failed review or shipped visibly broken. Three are now fixed; the last one is yours and gates everything downstream.

The icon was only 512×512 Fixed

You supplied new artwork - a flat oak-leaf illustration as SVG, 1024 and 512 PNG. It replaces the earlier photographic cutout, which is now unreferenced.

The traced SVG carried an opaque white square behind the leaf, which would have shown as a white tile in the macOS dock and on Linux dark themes. Removed, and verified the leaf renders intact without it. The generated .icns now has every slot through 512@2x = 1024.

Two fonts were referenced but never bundled Fixed

styles.css asked for 'Baloo 2' and 'Quicksand', but no font files shipped and nothing fetched them. Neither is installed on your Mac either - so the app had never rendered in its intended typefaces, in dev or in the build. It was falling back to Trebuchet MS throughout.

Fixed: both vendored as WOFF2 variable fonts (113 KB for latin + latin-ext), loaded via @font-face. Verified loading in the packaged app. Note this visibly changes the UI - it now looks the way the stylesheet always intended.

Bundled photos need provenance Done

17 cover photos and 5 backgrounds come from Pexels. The Pexels License permits bundling but is not an OSS license, so they sit outside MIT. Flathub reviewers do check this.

I wrote NOTICE covering all 22 files. One gap remains: leaf.png's origin is unknown - confirm you made it, or replace it, before publishing.

The project isn't under version control You

There's no .git directory yet, so there's no history to open source. Everything downstream - CI, Flathub's manifest pointing at a tagged commit, release automation - depends on this existing first.

3

Flathub

Free · review by volunteers
Do this one first

Cheapest, fully in the open, and the review feedback is genuinely useful before you face Apple's. It's also the most technically distinctive of the three, because the build runs offline in a sandbox.

  1. 1

    Manifest on the Electron base app

    com.roryok.bileog.yml built on org.freedesktop.Platform with org.electronjs.Electron2.BaseApp, which supplies the Chromium runtime libraries.

  2. 2

    Vendor npm dependencies for an offline build

    The single most common reason Electron submissions stall. Flatpak builds have no network, so npm install cannot run. Generate a sources manifest ahead of time:

    flatpak-node-generator npm package-lock.json -o generated-sources.json

    Watch better-sqlite3 specifically - it must compile from source inside the sandbox rather than downloading a prebuilt binary, so the manifest needs Python and the build toolchain available.

  3. 3

    AppStream metainfo and desktop entry

    com.roryok.bileog.metainfo.xml - summary, description, screenshots with captions, <content_rating type="oars-1.1"/> (all-null for this app), and a release entry. Plus com.roryok.bileog.desktop. Filenames must match the app ID exactly. Validate locally with appstreamcli validate before submitting.

  4. 4

    Sandbox permissions - keep them minimal

    Request no network at all. For file access, prefer the portal-backed file chooser over blanket --filesystem=home; your two dialogs (cover picker, story export) work through it. A tight permission set gets a faster review and earns the app a better privacy badge on the store page.

  5. 5

    Submit the pull request You

    Open a PR against flathub/flathub adding the manifest. A volunteer reviews it; expect comments and a round or two of changes. On approval you get a dedicated repo with write access, and future updates are PRs there.

  6. 6

    Verify ownership of roryok.com You

    Because the ID is com.roryok.bileog, Flathub verifies you via the domain - a DNS TXT record or a .well-known file on roryok.com. This is exactly why the ID had to be settled first. Verified apps get a checkmark on the listing.

4

Microsoft Store

Free to register
Needs a Windows build
  1. 1

    Open a Partner Center account You

    Microsoft has waived the old $19 individual registration fee - accounts are now free for individuals and companies alike. Registration replaced credit-card gating with identity verification (government ID plus a selfie), so budget a day or two for approval.

  2. 2

    Reserve the name "Bileog" You

    Do this the moment the account is live, before any build work. Reserving is free and instant, and it locks the identity values you'll need next.

  3. 3

    First Windows build of the app

    Nothing here has ever run on Windows, so treat this as real porting work rather than a config change. better-sqlite3 needs a win32 rebuild; the bileog-media:// protocol handler and every join() path need checking against backslash separators. Build on a windows-latest runner.

  4. 4

    Package as MSIX

    electron-builder's appx target, with identityName, publisher, and publisherDisplayName copied exactly from Partner Center - a mismatch is the classic rejection. The Store re-signs your package, so you don't need your own code-signing certificate.

    If MSIX fights you, the Store also accepts a plain .exe/.msi installer, which is a much shorter path for a first release.

  5. 5

    Submit with an age rating

    Fill in the IARC questionnaire. An offline writing app with no ads, no chat, and no data collection rates for all ages - say so plainly and the rating comes back clean.

5

Mac App Store

$99/yr · already enrolled
Most work of the three

Last, because it demands the most change: App Sandbox is mandatory, and it's a different build of Electron from the one you're shipping today.

  1. 1

    Certificates, App ID, provisioning profile You

    In the developer portal: a Mac App Distribution and a Mac Installer Distribution certificate, an App ID of com.roryok.bileog, and a Mac App Store provisioning profile saved as build/embedded.provisionprofile. Note these are different certificates from the "Apple Development" one already in your keychain - that one can't sign for distribution.

  2. 2

    Switch to the mas target

    Only the MAS build of Electron can run under App Sandbox, and electron-builder fetches it for you. Keep hardenedRuntime: false here - that's a Developer ID concern, not a MAS one - and set type: distribution. The existing ad-hoc DMG config stays as-is for direct downloads.

  3. 3

    Two entitlements files

    Your app needs a strikingly short list, because it never touches the network:

    com.apple.security.app-sandbox                    true
com.apple.security.files.user-selected.read-write true

    The second covers both file dialogs - the cover-image picker and the story export - which reach files through macOS's powerbox and work fine under sandbox. A matching *.inherit.plist signs the frameworks and helper processes. Deliberately absent: any network entitlement.

  4. 4

    Verify SQLite and PDF export under sandbox

    Two things to actually run, not assume. Sandboxing redirects userData into a container path, so confirm better-sqlite3 still opens the database and WAL mode works there. Then confirm the hidden BrowserWindow used for printToPDF still renders - child processes need the inherited entitlements to launch at all.

  5. 5

    App Store Connect listing You

    Create the record, upload via Transporter, then fill in privacy labels - yours is the rare honest "Data Not Collected" across every category. Rate it 4+.

    One judgement call: the Kids category brings extra scrutiny (parental gates, no third-party analytics) but also real discoverability for exactly your audience. Bileog already complies by construction. Worth taking, but expect a longer first review.

Why this order

Flathub first isn't about it being easiest - it isn't. It's that its review is public, thorough, and free, so it surfaces packaging and metadata problems while fixing them is still cheap. The metainfo, screenshots, and content rating you produce for it feed straight into the other two listings.

The Mac App Store goes last despite your account already being active, because sandboxing is the only step that can force changes to application code. Better to discover that with two stores already shipped than to have it block everything.
